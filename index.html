What this system is

A personally hosted alternative to consumer cloud storage: files stay on hardware you own, encrypted at rest, reachable only through an authenticated Tailscale tunnel rather than a public internet-facing endpoint.

PURPOSE

  • Replace Dropbox/Drive-style sync with a self-owned storage backend
  • Keep every file physically on a drive you control, not a third party's datacenter
  • Reach it from any device without opening ports to the public internet

KEY FEATURES

  • Flask REST API for upload, download, list, and delete operations
  • Per-user auth with hashed credentials, no plaintext passwords stored
  • Configurable storage root: D:\Storage or /mnt/storage
  • Structured local access logs for every read/write

THREAT MODEL

  • No open inbound ports on the public WAN — Tailscale closes that surface
  • Compromise of a single device does not expose the tunnel network key
  • Local logging gives a forensic trail for any access attempt

What this looks like at different scales

The same Flask core runs at every scale below — what changes is how it's fronted, how access is governed, and where the bytes physically live.

Aspect Scale 1 — Personal / Home1–5 devices Scale 2 — Small Business5–25 users Scale 3 — Enterprise / Cloud100+ users
Hardware Any spare PC/NAS, 4GB RAM, dual-core CPU is enough Dedicated mini-PC or rack unit, 8–16GB RAM, SSD boot drive Multiple VMs or containers behind a load balancer, provisioned per demand
Network overhead Negligible — Tailscale idles at near-zero bandwidth Noticeable during backup windows; plan for upload-heavy hours Sustained throughput planning; CDN/edge caching for static assets
Storage limits Bounded by a single local drive, typically 1–8TB RAID array or multiple mounted volumes, tens of TB Elastic object storage — effectively unbounded
Access control Single shared account or a couple of hardcoded users Per-user accounts, role flags (admin/staff), folder-level permissions SSO/OIDC integration, fine-grained IAM policies per bucket/object
Concurrent connections Flask's dev server or a single Gunicorn worker is plenty Gunicorn with 2–4 workers behind a process manager Horizontally scaled app instances behind Nginx/Caddy
Backup strategy Manual or scheduled copy to a second external drive Nightly automated snapshot to a second on-site NAS Versioned, geo-redundant object storage with lifecycle policies
Reverse proxy Not required — Tailscale terminates the tunnel directly Optional Caddy instance for a clean internal hostname Nginx or Caddy required, handling TLS + routing
Containerization Runs directly in a Python venv — no container needed Optional single Docker container for easy redeploys Docker + orchestration (Compose or Kubernetes)
Object storage Local filesystem only Local filesystem, optionally mirrored to cloud cold storage S3 or self-hosted MinIO as the primary backend
